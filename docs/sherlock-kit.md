# Sherlock toolkit migration

The toolkit lives in the [standalone sherlock-kit repository](https://github.com/FridrichMethod/sherlock-kit).
Consumer projects pin their own installation and declare project-local use.
Dotfiles no longer installs a launcher, toolkit rules, skills or a generated
Codex override, and no longer bumps the toolkit submodule.

On the next POSIX Stow, after config preflight and before Stow dry runs,
dangling home links are retired only when their resolved targets exactly match
this checkout's historical `lab-ubuntu`, `wsl-ubuntu` or `sherlock` package paths:
`.claude/rules/sherlock-kit.md`, `.claude/skills/sherlock-kit`,
`.agents/skills/sherlock-kit`, and `.local/bin/shk`. The old common/codex `shk`
and `codex-instructions-sync` launcher links are also retired. Skill directory
links are unlinked themselves; nothing recurses through them. Live or foreign
links and regular files are preserved.

After successful Stow, only a nonsymlink regular `~/.codex/AGENTS.override.md`
with this exact first line is removed:

```text
<!-- Generated by dotfiles codex-instructions-sync. Edit common/codex/.codex/AGENTS.md or the host's sherlock-kit rules, then rerun stow-all.sh. -->
```

Foreign overrides are preserved with a warning. Codex reads an override instead
of `AGENTS.md`; inspect and move obsolete manual overrides aside yourself.
Native Windows retires only the two exact dangling common/codex launcher links,
respecting `-WhatIf`, confirmation and `-Strict`. Inspect legacy Windows rules,
skills and overrides manually, including ownership of the older
`~/.local/bin/shk.cmd` launcher and `~/.local/share/sherlock-kit` installation.
No automatic deletion of these Windows entries or bulk home cleanup runs.

A pull may retain `common/sherlock-kit/sherlock-kit/` after the submodule is
removed. `.gitignore` and `.stowrc` keep it harmless even without its package
ignore file. The doctor warns with an exact manual removal command. Inspect
local branches and files before removing that checkout; retain and inspect
`.git/modules/common/sherlock-kit/sherlock-kit` until local work is recovered.
Neither is removed automatically. The pre-move coding-agent-kit checkout is
also reported, and its module store must stay because the current submodule
still uses it. See [coding-agent-kit.md](coding-agent-kit.md).
